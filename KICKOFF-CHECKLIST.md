# Repo Handshake Lite — Kickoff Checklist

Use this before starting client work.

## Client and commercial path

- [ ] Client name and primary contact recorded
- [ ] Preferred communication channel agreed
- [ ] Payment method and payment terms known
- [ ] Repository ownership is clear

## Scope lock

- [ ] In-scope outcomes written in observable language
- [ ] Out-of-scope items written explicitly
- [ ] Acceptance criteria exist for each important deliverable
- [ ] Delivery environment is identified

## GitHub

- [ ] Correct repository selected
- [ ] Issue types understood: Bug / Feature / Change Request
- [ ] Pull Requests must link to tracked work
- [ ] No secrets, tokens, passwords or `.env` files in Issues or Pull Requests

## Change Requests

- [ ] Any new request outside scope becomes a Change Request
- [ ] Timeline / price / scope impact is recorded
- [ ] **No implementation starts before Approved**

## Weekly delivery

- [ ] Review what actually merged
- [ ] Rewrite technical merges in client-facing language
- [ ] State blockers and who owns them
- [ ] State decisions needed
- [ ] State what is planned next

## Handoff reminder

Before closing the engagement, verify acceptance, document ownership and revoke temporary access.
